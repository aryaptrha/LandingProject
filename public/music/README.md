# Music files

Audio for the side-menu player lives here. Vite copies `public/` into `dist/`
verbatim, and `wrangler.toml`'s `[assets]` binding serves `dist/`, so a file
dropped in this folder is reachable at `/music/<name>.mp3` with no code change.
Requests never touch Hono or D1/KV — `src/worker/index.ts` only routes `/api/*`.

This file is the exception: `public/.assetsignore` excludes `*.md` from the
deploy, so these notes stay in the repo instead of being served at
`/music/README.md`.

## Adding a track

1. Put the file here, e.g. `public/music/lofi-morning.mp3`.
2. Add an entry to `MUSIC_TRACKS` in `src/data/musicTracks.ts`:

   ```ts
   { id: 'lofi-morning', title: 'Lofi Morning', artist: 'Someone', src: '/music/lofi-morning.mp3' },
   ```

The `src` must match the filename exactly, including case. The list order is the
play order; `id` only needs to be unique.

## Things worth knowing

- **Nothing is fetched until the visitor presses play.** The player builds its
  audio element on first play intent and assigns `src` only then, so adding files
  here costs the page nothing on load. It does add to repo size and
  `wrangler deploy` upload time.
- **Cloudflare Workers Assets caps a single file at 25 MiB.** A five-minute
  192 kbps MP3 is around 7 MB, so this is only a concern for long-form audio.
- **Binaries in git are permanent** unless history is rewritten. If this grows
  past a handful of tracks, move them to an R2 bucket instead of letting the repo
  carry them — that is the point to revisit the decision, not before.
- **Seeking works for free.** Cloudflare's asset server honours `Range`, so the
  browser fetches byte ranges rather than re-downloading.
- Prefer MP3 for the widest browser support. If you add other formats, check
  Safari support before relying on them.

## Placeholder tracks

The three `.wav` files here are synthesised, not licensed — four bars of a lofi
chord progression each, about 13 seconds at 16 kHz mono. They exist so the drawer
has something to play while the UI is being built, and they are deliberately
short so auto-advance is quick to observe.

They are generated by a standalone script (no dependencies, deterministic output
so re-running produces byte-identical files). To regenerate:

```
node scripts/gen-lofi.mjs
```

Delete them once real audio lands. Nothing in the app depends on them beyond the
three `src` strings in `src/data/musicTracks.ts`.

They are `.wav` because that needs no encoder. If the size bothers you before
real tracks arrive, transcode with ffmpeg and update the three `src` extensions:

```
ffmpeg -i dust-motes.wav -codec:a libmp3lame -b:a 64k -ac 1 dust-motes.mp3
```

## Licensing

Only add tracks you have the right to serve publicly. If a track needs
attribution, say so and a credit line can be added to the drawer footer.

For genuinely free sources: Pixabay Music is the least friction (Pixabay License,
commercial use, no attribution required), and incompetech.com is a large CC BY
catalogue that does require a visible credit. Both are from memory and unverified
— check the licence on the specific file before committing it.
